# CLAUDE.md — working on the VibeKit repo

> **Scope:** these are the rules for agents working **on this repository**.
> They are *not* the rules VibeKit ships to user projects — those live in
> [`master_prompt.md`](./master_prompt.md) and [`skill/SKILL.md`](./skill/SKILL.md),
> and are installed into a user's project by `npx @vibekit/cli init`.

## What this repo is

Four products in one repo. Only one of them compiles, which is the single most
important thing to know before changing anything.

| Surface | What it is | Verified by |
|---|---|---|
| Root `*.md` | **The actual product** — prompts consumed by LLM agents | Nothing automatic. Read carefully. |
| `registry/` | 144 shadcn-installable primitives in 17 categories | `typecheck/` + `scripts/validate-registry.mjs` |
| `web/` | Next 16 + React 19 + Tailwind v4 marketing/docs site | `pnpm build` (must stay green) |
| `cli/` | `npx @vibekit/cli init` | `npm test` in `cli/` (11 tests) |
| `typecheck/` | Compiles every primitive against shims of a real app | `npm run typecheck` |
| `public-templates/` | 14 starter templates | Not built here |

Everything runs in CI via `.github/workflows/ci.yml`.

**The registry used to be uncompiled.** Primitives ship as copy-paste files, so
they live outside any TypeScript project and `tsc` never saw them. Every bug in
the last audit — an unsigned auth cookie, three infinite render loops, two
cross-tenant data leaks — reached `main` because of that. `typecheck/` is the
fix: it maps each item's install target back to its source and compiles the lot.

It still can't see runtime behaviour — render loops, missing effect cleanup and
subscription leaks pass a typecheck. Re-read those by hand.

## Non-negotiables

### Registry
- Install syntax is **`pnpm dlx shadcn@latest add MUKE-coder/vibekit/<name>`**. Six
  legacy "feature units" live on `https://jb.desishub.com/r/<name>.json` instead.
- **Every file must be declared.** Each `.ts`/`.tsx` under `registry/<cat>/` must
  appear in exactly one item's `files[]` in that category's `registry.json`.
- **Every import must be declared.** A bare npm import → the item's
  `dependencies`. A `@/components/ui/*` or cross-primitive `@/lib/*` import →
  `registryDependencies`. An undeclared import is a broken install for every user.
- **Names are globally unique.** shadcn installs are flat-namespaced, so two
  items sharing a `name` in different categories silently overwrite each other.
- **`registry/INDEX.md` must stay in sync.** It is the discovery surface
  `/vibekit-find` greps. Its per-section counts and every `**name**` must match
  the real registry — an item advertised under a name that doesn't exist hands
  the user a command that 404s. Counts must sum to the real item total.

### Primitives (`registry/**`)
- Next 15+ made `cookies()`, `headers()`, `draftMode()`, `params` and
  `searchParams` **async**. Await them — including in docblock usage examples,
  which users copy verbatim.
- `"use client"` only where it's needed, and **never** on a module that reads a
  non-`NEXT_PUBLIC_` env var — it gets inlined as `undefined` in the client
  bundle and the feature silently never runs.
- Every effect that subscribes must unsubscribe: listeners, intervals,
  observers, `EventSource`, `BroadcastChannel`, `AbortController`.
- Never put an object or array literal in a dep array. Callers pass inline
  `{ id, name }` objects; depend on the primitive fields instead.
- Security-sensitive categories (`auth`, `security`, `payments`, `utilities`)
  must fail **closed**, sign anything client-held, compare secrets with
  `timingSafeEqual`, and claim idempotency keys **atomically before** running
  the handler, never check-then-write after.

### Web (`web/`)
- Tailwind **v4**, CSS-first. Tokens live in the `@theme` block in
  `globals.css`. **Do not create `tailwind.config.ts`** — it's ignored unless
  explicitly imported, so config placed there silently has no effect.
- `pnpm build` must stay green. Run it before you commit.
- Route handlers under `/r` are the shadcn install endpoint and are prerendered.
  **Exporting anything other than `GET` reverts them to per-request rendering** —
  don't add `OPTIONS` back.
- `readPrompt()` throws in production when a framework file is missing. That is
  deliberate: a silent stub used to ship a broken quickstart page on a green build.

### CLI (`cli/`)
- Zero runtime dependencies. Keep it that way — it runs via `npx`.
- `templates/` is generated by `scripts/bundle.mjs` and gitignored. Never commit
  it, and never hand-edit it; edit the source files at the repo root.
- Adding an agent means editing `src/agents.mjs`, `cli/README.md` **and**
  `skill/README.md` — those three drifting apart is the problem the CLI exists
  to solve.

## Before you finish

- Changed a primitive? `cd typecheck && npm run typecheck`, then
  `node scripts/validate-registry.mjs`. Both must be green. Also re-read the
  file for the things a compiler can't see: effect cleanup, dep arrays, and
  whether the security rules above still hold.
- Changed a primitive's name or added one? Update `registry/INDEX.md` — name,
  TRIGGERS, and the section count. `validate-registry.mjs` enforces this.
- Changed anything in `web/`? `cd web && pnpm build`.
- Changed anything in `cli/` or a file it bundles? `cd cli && npm test`.
- Changed a doc? Check whether the same fact is stated in another doc, and
  whether any relative link you touched still resolves.

Never edit `typecheck/shims/**` to silence an error — the shims model a user's
real project, so an error against them is normally a real defect in the
primitive. And never round-trip a `registry.json` through a JSON
serializer: it reformats every array and mangles em-dashes. Edit them as text.
