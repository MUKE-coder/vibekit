# `typecheck/` — the compiler the registry never had

The 144 primitives in `registry/` ship as copy-paste files. They live outside
any TypeScript project, so `tsc` never saw them. Every bug in the last audit —
an unsigned auth cookie, three infinite render loops, two cross-tenant data
leaks — reached `main` because nothing compiled these files.

This package compiles all of them.

```bash
cd typecheck
npm install
npm run typecheck
```

It runs in CI on every PR (`.github/workflows/ci.yml`).

## How it works

Primitives import each other by their **installed** path (`@/lib/db`,
`@/hooks/use-debounce`), not their repo path (`registry/utilities/db.ts`).
`scripts/gen-tsconfig.mjs` reads every `registry/<cat>/registry.json` and maps
each item's install `target` back to its source file, producing
`tsconfig.json`. That file is generated and gitignored — a hand-maintained map
would rot the moment someone adds a primitive, which is exactly the drift this
harness exists to catch. The generator also fails if two primitives claim the
same install path.

## The shims

A primitive expects to land in a real Next.js app that already has shadcn/ui, a
Prisma client and an auth layer. Those aren't in this repo, so `shims/` models
them:

| Shim | Stands in for |
|---|---|
| `shadcn-ui.ts` | `@/components/ui/*` — generated by `shadcn init` in a user's project |
| `shadcn-utils.ts` | `@/lib/utils` (`cn()`) |
| `prisma.d.ts` | the generated Prisma client |
| `project.d.ts` | `@/lib/auth`, `@/lib/auth-client` — the user's auth layer |

Interactive components and the Prisma extension callbacks are typed
**precisely**, not as `any`. That is deliberate: a loose shim makes
`onCheckedChange={(v) => …}` infer `v: any`, the file "passes", and the harness
reports noise instead of signal. A harness that cries wolf doesn't get run.

**Do not edit shims to make an error go away.** The shims model a user's real
project; if a primitive errors against them, the primitive is usually wrong. Only
touch a shim when it genuinely misrepresents what shadcn/Prisma/Better Auth
actually export.

### What this does and does not catch

Catches: syntax errors, unresolvable imports, wrong Next.js API usage (sync
`cookies()`/`params`), bad hook signatures, arity drift in library callbacks,
`undefined` slipping into a non-optional parameter, and type errors in a
primitive's own logic.

Does not catch: runtime behaviour, render loops, missing effect cleanup, or
whether a prop is *semantically* right for a shadcn component. Those need the
runtime smoke-test app described in `demo/PHASES.md`.

## Adding a primitive

Nothing to do here. Add it to `registry/<cat>/registry.json` as usual; the
tsconfig regenerates from the manifests on every run. If it pulls a new npm
package, add that package to this `package.json` too, or the harness can't
resolve it.
